# Заметки проекта

## Почему выбрана тема

Домашние запасы — понятная предметная область: продукты, категории, места хранения
и даты годности. Проект можно развивать в API с базой данных и контейнерным запуском.

## Цель MVP

Добавлять продукт, указывать срок годности, просматривать запасы и отмечать расход.

## Сущности

- Продукт: id, название, категория, количество, единица измерения, место хранения,
  дата покупки, дата окончания годности, статус.
- Категория: id, название.
- Настройки: число дней до окончания годности для предупреждения.

## Правила

- Порог предупреждения: 3 дня.
- Даты передаются в формате YYYY-MM-DD; расчёт по календарной дате Europe/Moscow.
- Истёкший срок: дата окончания годности раньше сегодняшней даты.
- Если дата годности сегодня, продукт попадает в предупреждение, но ещё не просрочен.
- Использованные и выброшенные продукты не входят в активные запасы.

## Дальнейшее развитие

Linux: запуск API и базы данных. Docker: образ сервиса.
Docker Compose: сервис и PostgreSQL. Архитектура: выделение расчёта годности.

## За пределами MVP

Авторизация, сканирование штрихкодов, push-уведомления, рекомендации рецептов.
Сервис учитывает введённые даты; оценка безопасности употребления в MVP не входит.
